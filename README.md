# Визуализатор графа зависимостей пакетов

Дисциплина «Конфигурационное управление», практическая работа №2, вариант 23.  
Группа ИКБО-66-25.

## 1. Общее описание

Инструмент визуализации графа зависимостей для менеджера пакетов **Rust (Cargo)**. Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются. Для работы требуется только **Python 3**, сторонние пакеты не требуются.

Реализованные этапы:
1. **Конфигурация**: параметры читаются из файла YAML и проходят строгую проверку.
2. **Сбор данных**: прямые зависимости пакета Rust (Cargo) берутся из репозитория crates.io по URL-адресу.
3. **Основные операции**: граф всех (в том числе транзитивных) зависимостей строится обходом **BFS с рекурсией**, циклические зависимости корректно обрабатываются, реализован режим тестового репозитория.
4. **Дополнительные операции**: режим вывода обратных зависимостей (какие пакеты зависят от заданного) тем же обходом BFS.
5. **Визуализация**: граф выводится на экран на языке диаграмм **Graphviz (DOT)**, картинка автоматически рисуется веб-сервисом Kroki, сохраняется в файл SVG и открывается в браузере; результаты сравнены со штатным инструментом `cargo tree`.

## 2. Функции и настройки

### Конфигурационный файл
Параметры задаются в файле формата YAML. По умолчанию читается `config.yaml` из текущей папки, другой файл можно передать аргументом командной строки. Поддерживается подмножество YAML: пары «ключ: значение», комментарии после `#`, строки в кавычках, значения `true` и `false`.

Пример конфигурации:
```yaml
package: serde
repository: https://crates.io
test_mode: false
reverse: false
image: build/graph.svg
```

- **`package`**: имя анализируемого пакета. Латинские буквы, цифры, `_` и `-`, начинается с буквы, не длиннее 64 символов.
- **`repository`**: URL-адрес репозитория или путь к файлу тестового репозитория. При `test_mode: false` это URL `http://` или `https://`, при `test_mode: true` — путь к существующему файлу.
- **`test_mode`**: режим работы с тестовым репозиторием, `true` или `false`.
- **`reverse`** (необязательный, по умолчанию `false`): режим вывода обратных зависимостей, `true` или `false`. Работает только при `test_mode: true`.
- **`image`** (необязательный): имя файла `.svg`, куда сохранить картинку графа (например, `build/graph.svg`). Если задан, картинка рисуется автоматически и открывается в браузере.

### Прямые зависимости из crates.io (Этап 2)
Для пакета берётся его последняя стабильная версия, затем список её зависимостей. Используется открытый API репозитория и только модули `urllib` и `json` стандартной библиотеки, утилита `cargo` не вызывается:
- `{repository}/api/v1/crates/{package}` — получение версии пакета.
- `{repository}/api/v1/crates/{package}/{version}/dependencies` — получение зависимостей.

Правила отбора:
- Зависимости для разработки (`dev`, нужны только для тестов самого пакета) пропускаются.
- Обычные зависимости и зависимости сборки (`build`) учитываются.
- Если имя встречается несколько раз (для разных платформ), оно берётся один раз.
- Необязательные зависимости (`optional`, подключаются через features) в граф не входят.

### Граф зависимостей (Этап 3)
Граф строится обходом в ширину (BFS) с рекурсией (`src/graph.py`): функция обрабатывает один уровень графа (сначала сам пакет, затем его прямые зависимости, затем их зависимости) и рекурсивно вызывает себя для следующего уровня, пока он не пуст.

Циклические зависимости обрабатываются корректно: пакет, который уже есть в графе или уже стоит в очереди, второй раз не обходится. Поэтому цикл `A -> B -> C -> A` и пакет, зависящий от самого себя, не приводят к бесконечной работе, а каждое ребро выводится один раз.

### Обратные зависимости (Этап 4)
При `reverse: true` выводятся пакеты, которые зависят от заданного, напрямую или через другие пакеты. Используется тот же обход BFS с рекурсией, что и на этапе 3, только по перевёрнутым рёбрам: функция `reverse_edges` из описания «A зависит от B и C» делает «от B зависит A, от C зависит A». Циклы обрабатываются так же.

Режим работает с тестовым репозиторием. Чтобы найти все пакеты, которые зависят от заданного, нужно знать весь репозиторий. В crates.io от популярных пакетов зависят десятки тысяч других, поэтому при `test_mode: false` параметр `reverse: true` считается ошибкой.

### Визуализация на языке Graphviz (Этап 5)
Граф, построенный обходом BFS, переводится в текст на языке диаграмм Graphviz (`src/dot.py`) и выводится на экран. Каждое ребро `"A" -> "B"` означает «A зависит от B», анализируемый пакет выделен цветом, каждый пакет и каждое ребро встречаются один раз.

Картинка рисуется автоматически, если в конфигурации задан параметр `image`:
1. Текст на языке DOT отправляется POST-запросом на веб-сервис Kroki (`https://kroki.io/graphviz/svg`), который рисует граф программой Graphviz и возвращает картинку SVG (`src/render.py`, модуль `urllib`).
2. Картинка сохраняется в файл из параметра `image`, папка создаётся при необходимости.
3. Файл открывается в браузере (модуль `webbrowser`).

Используется только стандартная библиотека Python, устанавливать Graphviz локально не нужно, требуется только доступ в интернет. Если сервис недоступен, текст DOT всё равно выводится, а программа сообщает об ошибке визуализации.

### Сравнение с cargo tree
Штатный инструмент Cargo для просмотра зависимостей: `cargo tree`. Для сравнения создан пустой проект с зависимостями `serde = "1"`, `rand = "0.10"`, `clap = "4"` и выполнено `cargo tree -p ИМЯ`.

**Общие отличия:**
- `cargo tree` рисует дерево: общая зависимость повторяется под каждым пакетом, а повторы помечаются `(*)`. Наш инструмент строит математический граф: каждый пакет и каждое ребро выводятся один раз, у общей зависимости несколько входящих стрелок.
- `cargo tree` показывает версии. Мы берём последнюю стабильную версию каждого пакета, а cargo выбирает последнюю версию, подходящую под требование (например, `syn ^3`) и под версию Rust.
- Необязательные зависимости (features) и условия платформ (`target`) наш инструмент не вычисляет: это работа настоящего менеджера пакетов, а готовые менеджеры пакетов по условию задания использовать нельзя.

### Тестовый репозиторий
При `test_mode: true` параметр `repository` указывает на текстовый файл с описанием графа. Пакеты называются большими латинскими буквами, каждая строка описывает пакет и его прямые зависимости через пробел:
```text
# комментарий
A: B C
B: D
C: D
D:
```
Каждый пакет, на который есть ссылка, тоже должен быть описан (пакет без зависимостей записывается как `D:`). Это проверяется сразу при чтении файла.

### Обработка ошибок
Проверяются все параметры конфигурации, и все найденные ошибки выводятся сразу. При любой ошибке программа завершается с кодом `1`.

| Ситуация | Сообщение |
|----------|-----------|
| Нет конфигурационного файла | `конфигурационный файл не найден: ...` |
| Строка без двоеточия | `строка 2: ожидается запись вида «ключ: значение»` |
| Ключ повторяется | `строка 3: ключ «package» повторяется` |
| Параметр не задан | `repository: параметр не задан` |
| Лишний параметр | `depth: неизвестный параметр` |
| Некорректное имя пакета | `package: некорректное имя пакета «1-bad-name!»` |
| Некорректный URL | `repository: некорректный URL-адрес «crates.io»` |
| Нет файла тестового репозитория | `repository: файл тестового репозитория не найден: ...` |
| Неверный режим | `test_mode: ожидается true или false, получено «maybe»` |
| Reverse без тестового режима | `reverse: обратные зависимости поддерживаются только при test_mode: true` |
| Файл картинки не .svg | `image: ожидается имя файла с расширением .svg, получено «graph.png»` |
| Пакет не найден в crates.io | `пакет не найден в репозитории: ...` |
| Пакет не описан в тестовом репозитории | `пакет D не описан в тестовом репозитории (на него ссылается B)` |

## 3. Сборка и тесты

Сборка не нужна, достаточно **Python 3.8** или новее.

```bash
# Запуск с конфигурацией по умолчанию
sh run.sh

# Запуск с другим файлом конфигурации
sh run.sh examples/stage3/test_cycle.yaml

# Запуск автотестов
sh scripts/run_tests.sh

# Демонстрация этапов
sh scripts/stage1_demo.sh    # Демонстрация ошибок конфигурации
sh scripts/stage2_demo.sh    # Пакеты crates.io и ошибки репозитория
sh scripts/stage3_demo.sh    # Граф на разных тестовых репозиториях (ромб, циклы, self-loop)
sh scripts/stage4_demo.sh    # Обратные зависимости
sh scripts/stage5_demo.sh    # Граф на языке Graphviz для serde, rand, clap
```
*Примечание: для `stage2_demo.sh`, `stage5_demo.sh` и примеров `real_*` нужен доступ в интернет. Автотесты сеть не используют: ответы сервера в них подменяются.*

## 4. Примеры использования

**Цикл в тестовом репозитории:**
```bash
$ sh run.sh examples/stage3/test_cycle.yaml
digraph dependencies {
    node [shape=box];
    "A" [style=filled, fillcolor=lightblue];
    "A" -> "B";
    "B" -> "C";
    "C" -> "A";
}
```

**Обратные зависимости пакета G в большом графе с двумя циклами:**
```bash
$ sh run.sh examples/stage4/big_G.yaml
digraph dependencies {
    node [shape=box];
    "G" [style=filled, fillcolor=lightblue];
    "C" -> "G";
    "A" -> "C";
    "G" -> "C";
    "D" -> "A";
    "A" -> "D";
}
```

**Настоящий пакет из crates.io с автоматической отрисовкой:**
```bash
$ sh run.sh examples/stage5/clap.yaml
digraph dependencies { ... }
изображение графа сохранено и открыто: build/clap.svg
```

**Ошибки во всех параметрах конфигурации сразу:**
```bash
$ sh run.sh examples/configs/err_all.yaml
ошибка конфигурации (examples/configs/err_all.yaml):
  package: некорректное имя пакета «-bad» (...)
  test_mode: ожидается true или false, получено «1»
  repository: некорректный URL-адрес «ftp://crates.io» (...)
```
